# Kick75 IO side-light protocol notes

本文保存 Windows 实现使用的 NuPhy Kick75 IO HID 协议证据。它不是官方规范；字段名称来自固定上游
实现的行为验证和 NuPhyIO 公开客户端静态分析，固件更新后可能变化。M0 尚未在 Windows 上执行协议
读写，真正支持状态以硬件测试矩阵为准。

## 上游已验证设备

```text
Product:   Kick75 IO
USB VID:   0x19f5
USB PID:   0x1026
Report:    64-byte input and output
Interface: Usage Page 0x01, Usage 0x00
```

Pixelmoss `v0.2.0` 曾在 macOS 上通过 IOKit 访问 report ID `0`。这只是协议来源证据，
不代表 Windows HID transport 已完成。

## 帧格式

每个输入/输出报告固定为 64 字节：

| 偏移 | 长度 | 含义 |
| --- | --- | --- |
| `0` | 1 | 方向标志：主机写 `0x55`，键盘响应 `0xaa` |
| `1` | 1 | 命令字 |
| `2` | 1 | 保留，当前写 `0x00` |
| `3` | 1 | 校验和 |
| `4` | 1 | 数据长度，与会话密钥 XOR |
| `5..6` | 2 | 小端地址，与会话密钥 XOR |
| `7` | 1 | 句柄/会话字段 |
| `8..63` | 56 | 数据载荷 |

校验算法：

```text
checksum = sum(report[4..63]) & 0xff
```

## 临时会话密钥

灯光状态读写前发送命令 `0xee`。当前实现：

1. 生成 56 字节随机数据，写入偏移 `8..63`。
2. 选择报告偏移 `28` 的随机字节作为临时会话密钥；如果为零则使用 `0xaa`。
3. 写入校验和并发送。
4. 验证响应方向为 `0xaa`、命令为 `0xee`。

后续报告的长度、地址、句柄和有效载荷均使用该单字节密钥 XOR。
这是一种协议级掩码，并非密码学安全加密。

## 灯光命令

| 命令 | 值 | 用途 |
| --- | --- | --- |
| `SetSecretKey` | `0xee` | 建立临时会话密钥 |
| `GetLightState` | `0xd5` | 读取 17 字节灯光状态 |
| `SetLightState` | `0xd6` | 写入指定灯光状态片段 |

读取灯光状态时：

```text
length  = 17
address = 0
handle  = 0
```

解码后的 17 字节由两个区域组成：

```text
bytes 0..8   主键区状态（9 字节）
bytes 9..16  侧灯状态（8 字节）
```

固定上游只写侧灯区域，地址为 `9`、长度为 `8`；Windows M1 必须保持相同边界。

## 侧灯 8 字节状态

根据当前固件和客户端解析器：

| 相对偏移 | 含义 |
| --- | --- |
| `0` | 模式 |
| `1` | 亮度，范围 `0` 到 `100` |
| `2` | 速度编码 |
| `3` | RGB/模式标志 |
| `4` | 保留或模式附加字段 |
| `5` | 红色分量 |
| `6` | 绿色分量 |
| `7` | 蓝色分量 |

键盘测试前读取到的侧灯状态示例：

```text
00 64 01 01 00 e9 ff fb
```

静态颜色使用模式 `0x02`：

```text
红色: 02 64 01 00 00 ff 00 00
黄色: 02 64 01 00 00 ff b4 00
绿色: 02 64 01 00 00 00 ff 00
```

亮度字节接受 `0` 到 `100`，最后三个字节接受任意 RGB 分量。Windows 实现必须从经过验证的配置
动态生成这 8 字节，不能把示例颜色当作固定写入值。

## 恢复策略

Windows HID worker 第一次从空闲状态切换到状态色时必须：

1. 使用 `GetLightState` 读取完整灯光状态。
2. 保存侧灯原始 8 字节，不重新解释或重建它。
3. 写入当前任务状态配置的静态颜色与亮度。
4. 回到空闲时用 `SetLightState` 原样写回保存的 8 字节。

这种方式可以恢复用户原本的模式、颜色、亮度和速度，而不假设其具体含义。未来本地页面的预览也只能
请求托盘 Host 执行；页面不得直接访问 HID。预览结束后必须恢复原 baseline 或重新应用当前任务状态。

## 不使用的命令

Windows 实现不得发送：

- 固件升级命令。
- 恢复出厂命令。
- 键位映射命令。
- 主键区灯光写入。
- 未经行为验证的 HID 报告。

## Bluetooth 限制

蓝牙键盘输入可以正常使用，但当前发现的蓝牙接口不提供与 USB Raw HID 等价的 64 字节任意 RGB
写入通道，因此不进入灯控白名单。Windows MVP 只面向 USB `19F5:1026` 与 U1 2.4G 接收器
`19F5:2620`；两条 transport 都必须通过各自的 M1 恢复闸门。
